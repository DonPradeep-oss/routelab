1. The routing problem

A delivery partner starts at a source, must visit a set of stops (each exactly once) and finishes at a destination. Find the visiting order with the smallest total distance. This is the Travelling Salesman Problem with fixed start and end (an open-path TSP), which appears in courier, school-bus and field-service planning.

  • Inputs: source, destination, a list of up to 10 stops. Distances come from the latitude/longitude of real Bengaluru localities (Haversine formula × 1.3 road-winding factor).
  • Outputs: ordered route, total distance (km), estimated time (at 22 km/h city average), nodes explored and run time (ms).

2. Chosen algorithms

Greedy (nearest neighbour): from the current place, always travel to the closest unvisited stop, and finish at the destination. Very fast, but short-sighted: an early cheap move can force a long detour later.

Backtracking (DFS with branch and bound): build the route stop by stop, exploring every ordering. When the distance so far is already at least as large as the best complete route found, that branch is abandoned (pruned) and the algorithm backtracks. It always finds the optimal route.

4. Complexity

Let n be the number of stops.

AlgorithmTimeSpace
GreedyO(n²): n steps, each scans up to n stopsO(n) route + O(n²) distance matrix
Backtracking (no pruning)O(n!): every permutation is triedO(n) recursion depth + O(n²) matrix
Backtracking (branch and bound)O(n!) worst case, far less in practiceO(n) recursion depth + O(n²) matrix
